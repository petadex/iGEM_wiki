### Main Function(s) + Requirements

<br />

This iteration of the data and controls subsystem was heavily focused on improving the user interface. In addition to the basic purpose of developing the software (to receive and transmit data and controls to and from the bioreactor), making the data easy to read and making the controls easy to use were heavily emphasized.

This was important since in the V1 iteration, the user interface was difficult to use as the user had to type in command-line prompts and read data from the serial line. This made the software unapproachable; since the user interface itself is what the users would interact with, it is important to make the software easy to use to encourage users to actually make use of it.

No requirements were removed, but the priority of controlling multiple bioreactors in parallel slightly decreased, as developing a full proof-of-concept for the software’s function for one bioreactor can easily allow scaling.

### Design Modifications

After receiving feedback during the poster session at the Microplastics conference, the importance of a user-friendly software interface was highlighted. Thus, the user interface was modified to become more user-friendly.

First, colours were used to increase ease of navigation, the interface screen increased in size to increase the space between the components, and tabs were added to classify information based on relevance, as shown below:

### New Design of Experiments

#### Experiment 1: Testing the Python software compatibility with Arduino

To determine whether a Python based user interface could support two-way communication with the Arduino, a prototype dashboard was developed using Tkinter. We tested whether the software could successfully receive data from the Arduino and transmit controls to the hardware.

#### Experiment 2: Testing graphing functionality

To validate the temperature and spectrophotometry graphing features that were implemented in this iteration, sample data were loaded onto the Arduino prior to testing. The data were then transmitted to the software and displayed in their respective graphing tabs: temperature and spectrophotometry. We evaluated whether the data could be successfully transmitted, parsed, and plotted by the software, confirming the functionality of the graphing features.

#### Experiment 3: Testing ease of set up

Since the goal of this iteration was to improve user-friendliness of the interface, to evaluate the accessibility of the software, the procedure required launching the user interface. We assessed the number of steps required to open the software and access the user interface, with the goal of minimizing setup complexity and making the software easier for users to utilize.
