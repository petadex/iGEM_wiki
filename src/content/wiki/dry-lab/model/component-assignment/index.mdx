<Callout title="Methods for component assignment">
This page is the full write-up behind the [Component Assignment](/dry-lab/model/#component-assignment) subsection of the Model page. It picks up where [PETadex-PAZy Reference Curation](/dry-lab/model/plasticome/) ends, with 609 enzymes clustered at 90% identity into 411 centroids.
</Callout>

## Why components?

The next steps of PETadex search public sequence databases for relatives of PETadex-PAZy, and both the searches and the profile models that filter their results are built per family. A component is our working definition of a family. We use the same definition as the Logan preprint: a set of PETadex-PAZy enzymes joined to each other by chains of clear sequence similarity.

We can't treat PETadex-PAZy as one family. It contains several unrelated folds (see [CATH Assignment](/dry-lab/model/#cath-assignment)), and sequences from different folds don't align in any meaningful way. Components split it into groups that can each be aligned and searched on their own.

## Inputs

We start from the 411 cluster centroids we got by clustering PETadex-PAZy at 90% identity. Clustering first stops near-identical enzymes from adding hundreds of redundant alignments. Cluster members aren't aligned here; each one just joins the component of its centroid, which it matches at 90% identity or more.

Each centroid is one node in the graph, identified by the MD5 hash of its sequence (letters only, upper case), so identical sequences from different records end up as one node. All 411 centroid sequences are distinct, which gives 411 nodes and 144,560 residues in total.

## All-against-all alignment

We aligned every centroid against every other with USEARCH v11, using local alignment and keeping every hit, however weak:

```bash
usearch -allpairs_local combined.fasta -acceptall -userout combined_pairs.tsv \
    -userfields query+target+id+evalue+bits
usearch -allpairs_local combined_rev.fasta -acceptall -userout combined_rev_pairs.tsv ...
```

`-allpairs_local` only aligns each sequence against the ones after it in the file, so a pair can come out differently depending on which sequence is the query. To get around this, we ran the search twice (once on the reversed file) and pooled both outputs. This gave 62,223 alignments over 30,588 distinct pairs. For each pair we keep the alignment with the highest bit score (ties go to the lower E-value), so every pair is judged on one alignment.

We don't apply any threshold during the search. All the filtering happens afterwards on the saved alignments, so we can change the cutoff and recompute the components without aligning again.

## When two centroids are linked

Two centroids are linked if their best alignment has both:

- **at least 30% amino acid identity**, and
- **an E-value below 10<sup>−5</sup>**, as reported for this search (a database of 144,560 residues).

The E-value rule removes short, chance alignments that reach 30% identity over a few dozen residues. The identity rule removes long alignments between distant relatives, whose E-values are only small because the sequences are long. 22,203 of the 30,588 aligned pairs pass both.

## Connected components

The links form a graph, and each connected piece of it is one component. Two centroids are in the same component if a chain of links joins them, even if they aren't linked directly (single linkage). Components are numbered by size, largest first.

We use connected components instead of assigning each centroid to its single best match, because best-hit assignment breaks up families that are continuous. Take a chain A–B–C where A and C are too distant to align: depending on which of B's matches scores higher, it can end up as two groups. Families like the α/β-hydrolases are exactly these kinds of chains, with distant members joined through intermediates.

## Choosing 30%

The cutoff decides how coarse the components are. We re-ran the partition at other identity cutoffs on the same alignments and scored each one against the CATH superfamily of each centroid's catalytic domain. We call a component "mixed" if it contains more than one catalytic superfamily.

| Identity cutoff | Components | Single centroids | Largest | Mixed components | Centroids in their component's majority fold |
|---|---|---|---|---|---|
| 20% | 29 | 14 | 270 | 1 | 98.8% |
| 25% | 29 | 14 | 270 | 1 | 98.8% |
| **30% (used)** | 46 | 25 | 232 | 0 | 100.0% |
| 35% | 72 | 49 | 215 | 0 | 100.0% |
| 40% | 97 | 65 | 202 | 0 | 100.0% |
| 50% | 156 | 129 | 196 | 0 | 100.0% |
| 60% | 199 | 163 | 134 | 0 | 100.0% |
| 70% | 260 | 221 | 56 | 0 | 100.0% |

30% is the loosest cutoff where no component mixes folds. Below it, the five subtilisin-family protease centroids join an α/β-hydrolase component. Above it, components only break into smaller pieces of the same fold, so nothing is gained in purity and each family just gets split into more, smaller searches.

The α/β-hydrolase fold alone spans 27 components: its members are related by structure, but many are too distant in sequence to be linked at 30%. ## USEARCH or DIAMOND

Two steps depend on an alignment engine: clustering at 90% (which sequences become centroids) and this all-against-all alignment (how centroids group into components). To see how much the components depend on that choice, we ran all four combinations of USEARCH and DIAMOND on the same input, with the same linking rule.

| Clustering | Alignment | Centroids | Aligned pairs | Links | Components | Single | Largest |
|---|---|---|---|---|---|---|---|
| DIAMOND | DIAMOND | 404 | 27,259 | 20,736 | 48 | 25 | 218 |
| DIAMOND | USEARCH | 404 | 28,755 | 20,616 | 47 | 26 | 224 |
| USEARCH | DIAMOND | 413 | 29,343 | 22,536 | 47 | 25 | 229 |
| **USEARCH | USEARCH | 413 | 30,859 | 22,415 | 47 | 26 | 233** |

**The aligner barely matters.** With the clustering held fixed, 42 of 47 components are identical with either aligner, and six or seven centroids cross a component boundary on links close to the cutoff. DIAMOND reports fewer aligned pairs, but passes about 120 more links.

**The clusterer only matters through the centroids.** With the USEARCH aligner, the 295 centroids both clusterers chose keep exactly the same components; with DIAMOND, two move. The real difference is which centroids there are, and how many (404 vs 413).

In every combination, the second to fifth largest components have 45, 19, 16 and 14 centroids. Only the big α/β-hydrolase component changes size, from 218 to 233, as distant members join or leave it. So the partition is stable to the choice of engine, and we use USEARCH for both steps. Note that this comparison ran on an earlier version of the union, so its counts differ slightly from the final run.

## Checks

- **It reproduces the original PETadex components.** The same code, run on the 213 sequences of the original PETadex seed set, gives the published 42 components (3,178 links).
- **Old component labels hold up.** 166 centroids carry a component label from the original set. We only compare against these labels afterwards; they're never used to build the partition. No old component is split across two new ones.
- **Identical sequences can't be separated.** Nodes are sequence hashes, so two records with the same sequence are always in the same component.

## Back to 609 enzymes

Each of the 609 PETadex-PAZy enzymes takes the component of the centroid of its 90% cluster: 411 are centroids themselves, and the rest are cluster members. The result is one table with a row per enzyme, giving its cluster, its centroid, its identity to that centroid, and its component. [CATH Assignment](/dry-lab/model/cath-assignment/) uses this table to separate catalytic from accessory domains, and later steps search by the component column.

## About the component map

The component map on the Model page is drawn to be readable, not as the assignment itself. It shows all 609 enzymes rather than only the centroids, and uses DIAMOND with an extra rule that an alignment has to cover at least half of the shorter sequence. That rule cuts some long-range links inside the α/β-hydrolase family, which is why the map shows 56 components instead of 46. Almost every component on the map lies inside one component of the assignment. The exceptions are three α/β-hydrolase enzymes that sit with a different α/β-hydrolase group on the map than in the assignment. Highlighting a component on the map uses the assignment, so one highlighted component can cover several halos.

## Limitations

- **One link is enough.** Single linkage joins two groups through one alignment. That's what keeps continuous families together, but it would also merge two families if a single spurious alignment passed both rules.
- **No coverage rule.** A link can come from an alignment over just part of each sequence, e.g. a shared accessory domain. The fold check above found no component that mixes catalytic folds at 30%.
- **Components aren't folds.** Distant members of one fold land in separate components. Fold-level grouping comes from CATH, not from this step.
- **Single centroids.** 25 centroids have no link at all. Each one still gets searched, but as a family of one.

## Reproducing

Component assignment is step 3 of the PETadex-PAZy pipeline. One driver runs it together with the steps around it:

```bash
./pipeline_run.bash <run-name> --engine usearch --to 6
# step 3 alone, on an existing cluster table
ENGINE=usearch "lib/03 alignment/run_from_clusters.sh" runs/<run>/02-clusters.tsv
```

USEARCH v11 is a Linux binary, so it runs in Docker. The step writes `03-alignment.tsv` (the cluster table with a `component_id` column), the per-enzyme table `05-union-with-components.tsv`, and every intermediate file (alignments, links, component members, run statistics) under `03-alignment.intermediates/`.
