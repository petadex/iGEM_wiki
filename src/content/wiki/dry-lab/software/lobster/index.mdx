# LOBSTER Algorithm

IMAGE: Lobster Logo

To maximize our Wet Lab activity validation efficiency, we developed the LOBSTER (Library Optimization for Bioprospecting Sequences Through Economical Recombination) algorithm. Rather than naively purchasing full-length DNA sequences for each PETase core, LOBSTER utilizes Golden Gate fragment assembly and degenerate codons to create efficient fragment pool designs that can be combinatorially assembled to form a library of full-length cores. LOBSTER seeks to maximize the number of PETadex natural PETase cores which are generated in the resulting full-length library, which we define as coverage. To keep the generated libraries experimentally feasible, this coverage optimization is run subject to nucleotide quantity and library size constraints. By running LOBSTER on  90pid clusters, we can experimentally validate them for a fraction of the nucleotide cost (~45%), greatly expanding our full validation space. Additionally, since the full cores are combinatorially assembled, Golden Gate assembly will create cores not found in the PETadex. While these chimeras of naturally-occurring mutations were not identified through natural sequencing, it is still plausible that they show plastic-degrading activity. This further expands our Wet Lab validation space of potentially active PETases.

## Previous Work/Novelty

Existing library codon optimization algorithms such as SwiftLib (2015) [@jacobs2015swiftlib], and DeCoDe (2020) [@shimko2020decode] share the goal of maximizing target library coverage using minimal purchases, but only use degenerate codons to introduce variation. GGAssembler (2024) [@hoch2024ggassembler] introduces fragment assembly but considers coverage to be position-independent. In our case, coverage occurs on the sequence level, and multiple mutations must occur to fully cover desired PETase sequences. LOBSTER’s novelty therefore comes from the fact that it considers both degenerate codon and fragment operations in designs to maximize coverage on a sequence level.

## Methods

FIGURE 1: overview.png

### Preprocessing

First, we preprocessed PETadex 90pid clusters to create the input to LOBSTER. To do so, we ran HMMsearch using PETadex HMMs on the full ORFs within a 90pid cluster to extract the specific PETadex component regions, notated as cores throughout this write-up. Then, the cores were weighted by the number of ORFs corresponding to each core, in order to maximize PETadex coverage.

### Cut-Search

FIGURE 2a: cutsearch.png

Given a valid weighted core FASTA, LOBSTER works by identifying possible Golden Gate cut sites and then finding optimal cut site configurations to capitalize on naturally conserved regions. To do so, we adapted the site-directed recombination graph from RASPP (2004) [@endelman2004raspp]. As shown in Figure 2a, the nodes in the graph represent possible cut sites, and the edges encode how much variation would be created at the fragment position defined by the chosen cut site. The shortest path in this formulated graph represents the cut configuration with the least variation within fragment positions, which lowers the upper bound on nucleotides purchased. For the full algorithm, the top-5 shorted paths are computed using DP, and verified to ensure the orthogonality of Golden Gate overhangs. Additionally, because the graph solution is not guaranteed to lead to the fully optimal solution, random cut configurations are also chosen and input into the greedy loop.

### Greedy Loop

FIGURE 2b: greedy.png

Once the cuts are fixed, the algorithm greedily selects cheap cores to add to the solution until a cap (nt or library size) is reached. Specifically, given a current solution, for each core the algorithm computes what operations (mixed base addition, new fragment addition) it would take to include this core. The algorithm then takes the core whose required operations maximize total weighted coverage gain divided by the increase in full sequences added to the overall library. We notate this metric as gain/lib growth. An example greedy choice is visualized in Figure 2b. This loop terminates when a cap is reached, or when full coverage is achieved.

## Results

Two 90pid clusters, one containing IsPETase and the other containing LCC, were chosen as positive literature controls for LOBSTER and the wet-lab protocol. LOBSTER’s output designs for the IsPETase and LCC clusters saved 13,874 and 6,104 nucleotides respectively, as shown in Figures 3a and 3b. This led to a significant price reduction for the oligo pool order, while retaining the vast majority of PETadex cluster cores, as shown in Figures 3a and 3b. Additionally, the algorithm runs in polynomial time to the input size due to its greedy assumption. This allows for reasonably fast computation on the chosen clusters, with both algorithms finishing their computation over all possible numbers of fragments within 20 minutes, as shown in Figures 4a and 4b.

## Discussion

LOBSTER is an effective algorithm for economizing general oligo-pool assembly orders. We have observed significant nucleotide and cost reductions, without significant loss of PETadex coverage across our testing clusters. Future work on LOBSTER should investigate placing cut sites at more varied positions, additional formulations for the cut search stage, and proving approximation ratios for similar problems. We also plan to run LOBSTER on a larger set of PETadex v2 clusters predicted by our model, for future bioprospecting.
